# dnSpy modernization plan

Next work (after 2026-10-28) is tracked in [TODO.md](TODO.md).

Branch: `0000_Update`. Started 2026-10-23.

## Ground rules

- **Backward compatibility:** `dnSpy.Contracts.*` is the public extension API. Changes are additive only; nothing is removed or renamed without an `[Obsolete]` period. User settings files (`dnSpy.xml`) must keep loading.
- **Targets:** keep `net48` (the .NET Framework host) and replace `net5.0-windows` with `net10.0-windows` (current LTS). Whether to drop `net48` is decided at the end of Phase 6, not before.
- **One phase per PR-sized chunk.** Each phase ends with a green build of both TFMs and a smoke test: start the app, open an assembly, decompile it, edit a method, and debug a hello-world app (.NET Framework + .NET 10).
- Submodule forks (ILSpy 2.3, NRefactory, Roslyn EE, Mono.Debugger.Soft) are only touched in the phase that owns them.

## Phase 5: Modern ILSpy decompiler (side by side)

1. ✅ **Spike:** decompile from a dnlib `ModuleDef` with ICSharpCode.Decompiler (11.1.0.9782, the latest stable; 9.x was the plan's guess, 11.x is still netstandard2.0 and needs System.Collections.Immutable/Metadata 9.0, which net48 already has as 10.0). The module is written with `MetadataFlags.PreserveAll`, loaded as a `PEFile`, and tokens map back through the dnlib writer's metadata (318/318 methods matched). Local names come from the PDB dnlib already loaded (`IDebugInfoProvider` over `PdbState`). Still to prove: the IL offset ↔ text maps (`MethodDebugInfo`).
2. ✅ (basic) New extension `Extensions/ILSpyModern.Decompiler`: `dnSpy.Decompiler.ILSpyModern.Core` (the `IDecompiler`, also loaded by dnSpy.Console) and `dnSpy.Decompiler.ILSpyModern.x` (MEF export, content type). Language "C# (ILSpy 11)", GUID `8E0CBE51-4A6E-4C8C-9B3E-2D6D6C1F8A11`, ordered right after the old C# language. The old 2.3-based languages stay as they are.
   - Name clash: the package's `ICSharpCode.Decompiler.dll` has the same name and public key as the 2.3 fork (2.3.1.0 vs 11.1.0.9782), so they can't share a bin dir (and .NET has one default load context). `RenamedICSharpCodeDecompiler.targets` rewrites the package assembly at build time with dnlib (inline `RoslynCodeTaskFactory` task using `Build/compiled/dnlib.dll`) as `dnSpy.ICSharpCode.Decompiler`, signed with `dnSpy.snk`. The 2.3 fork keeps its identity, so extensions that use it still load.
   - References: a `TokenWriter` that writes to `IDecompilerOutput` maps ICSharpCode symbols back to dnlib definitions (main module through the writer's token map; other modules by token), plus `ILVariable`/`let` locals. Assembly references go through dnSpy's dnlib resolver; when it finds nothing (dnSpy.Console, .NET Core targets) through ICSharpCode's `UniversalAssemblyResolver`.
   - ✅ Converted-module cache (`ConvertedModuleCache.cs`): LRU lists shared by all decompilations, 4 main modules (written to memory) and up to 128 referenced files / 256 MB (validated by file size + time). Each entry is a `Lazy` created outside the lock, so one module is converted once even when several threads ask. `ConvertedModule` keeps two token maps instead of dnlib's writer `Metadata` (much smaller). The signal is `IDocumentTabService.DocumentModified` (every Assembly Editor command/undo/redo and the debugger's in-memory module updates call `RefreshModifiedDocument`), handled by `ConvertedModuleCacheUpdater` in the `.x` project, plus document Remove/Clear. `DocumentTabService.RefreshModifiedDocument` now raises the event before refreshing the tabs (tabs decompile on another thread, so after was a race). Measured (headless, `IDecompiler` API, one context per method like the GUI): System.Private.CoreLib `String` methods 430 → 7 ms each after the first, dnSpy.dll 63 → 30 ms. First decompilation of a big module still pays the write (CoreLib ~3 s).
   - ✅ Namespace references: `DecompilerOutputTokenWriter.GetNamespaceName` writes a `NamespaceReference` (assembly null; no consumer uses it) for each part of a using's or namespace declaration's name (`SimpleType`/`MemberType` chain, prefix up to that part; `global` skipped) and for namespace parts of qualified type names (ICSharpCode.Decompiler annotates them with `NamespaceResolveResult`; before, they were written without a reference). Colored as namespaces (before, the inner parts of a dotted namespace declaration were plain text).
   - ✅ Token/RVA comments (`TokenComments.cs`, option `ShowTokenAndRvaComments`, old GUID and name `--tokens`, default on like the old language, saved and on the settings page): added to the finished syntax tree as the entity's leading trivia (after the XML doc comment) with a `CommentReferences` annotation; `DecompilerOutputTokenWriter.WriteComment` writes the token as a `TokenReference` and RVA/file offset as `AddressReference`s. Same order as the old language (member, then get/set, add/remove, delegate `Invoke`). Not added to Edit Method/Edit Class code.
   - To do: `DecompileNamespace` (the base class lists the types, same as the old language).
   - ✅ XML doc comments: `DnlibDocumentationProvider` (ICSharpCode.Decompiler `IDocumentationProvider`) maps the entity back to the dnlib definition and uses dnSpy's `XmlDocLoader` / `XmlDocKeyProvider`, like the old language; `///` comments are written with the XML doc colors. Option `ShowXmlDocumentation` (old GUID and name, `--xml-doc`), saved and on the settings page.
3. ✅ (statements, locals) Debugger statement mapping: `DecompilerOutputTokenWriter` implements `ILocatable` (line starts are recorded, columns come from `IDecompilerOutput.NextPosition`, so indentation is included), the AST is written through `TokenWriter.WrapInWriterThatSetsLocationsInAST`, and `MethodDebugInfoCreator` turns `CSharpDecompiler.CreateSequencePoints` into `MethodDebugInfo` per `ILFunction` (MoveNext + kickoff method for async/iterators, lambdas and local functions; expression trees skipped). Locals map by IL local index or `StateMachineField`; hoisted parameters by field name (ICSharpCode.Decompiler doesn't record their field). Method span = the function's outermost AST node.
   - ✅ `AsyncMethodDebugInfo` (`AsyncMethodDebugInfoCreator.cs`), from the `MoveNext` IL (one code path, PDB or not): the state field is the first `int` field MoveNext loads; a yield is `state = N` (N ≥ 0) followed by an `Await(Unsafe)OnCompleted` call, its offset is the next instruction (like the old AsyncDecompiler); the resume offset comes from following the state dispatch (`switch`, `brfalse`/`brtrue`, compare-and-branch, `sub`+`switch`, `ldloc; pop`, nested try dispatch) with state = N; builder field/`SetResult` offset from `this.<builder>.SetResult(...)`; catch handler offset (async void only) from the catch that calls `SetException`. ILSpy only maps the `await`'s first IL range, so the unmapped IL around each yield (up to `GetResult()`) is mapped to the statement whose range ends where it starts.
   - ✅ Imports and `CompilerName`: the root scope's imports are the syntax tree's `using` namespaces (`UsingDeclaration`, same for every method in the output, like the old language's `UsingNamespaces`); the compiler name is set for state machines only, from the state machine type's name (`VB$StateMachine_` → VB, `<…>d__` → C#, `<…>c__Iterator`/`c__async` → Mono), the old language's rule.
   - ✅ Nested local scopes (`MethodDebugInfoCreator.AddLocals`): each local goes to the scope of the innermost `BlockStatement` of its function that contains all AST nodes annotated with its `ILVariable` (root scope if that's the function's body or the local isn't in the text). A block's IL span is min..max of its instructions' IL ranges (this function's only) and of the statements whose text is inside it; blocks are added outer first, and one whose span isn't inside the parent's or overlaps a sibling's gets no scope (its locals go to the parent). Then each scope is extended over the unmapped IL around it (brace nops), up to its siblings/parent. Duplicate locals (same name and same IL local/field) visible in the same chain are removed. The EE takes local names from the containing scopes and hoisted-local scope records from the scope spans.

   - ✅ Switch expressions (`SwitchExpressionTransforms.cs`): `ConditionalToSwitchExpressionTransform` turns a `?:` chain over a compiler temporary (integer or `decimal`, generated name, declared right before and used only by the chain) into `temp-initializer switch { ... }`. The values are split into atoms by the compared constants (bit masks), each leaf gets its set, and the arms are ordered (by highest value) so that each arm but the last is a single constant or relational pattern selecting exactly its set; the last is `_`. `InlineLambdaTemporariesTransform` turns `{ T a = ...; T b = ...; return new { A = a, B = b, ... }; }` lambdas (generated names, each used once, in order, same type ignoring nullability) back into expression lambdas. `RemoveEmptyConstantIfTransform` drops `if (1 == 0) { }`. `ModernCSharpOutputVisitor` writes `< 4` (ILSpy: `<4`) and no trailing space after the arms' commas. `MethodDebugInfoCreator` maps all of an expression lambda body's IL to the body (ICSharpCode.Decompiler only keeps a statement's first contiguous IL range); for lambdas that aren't state machines that's everything from the body's first to its last IL byte not mapped by another statement, which also covers IL that no instruction keeps after the transforms (cached delegate initialization of nested lambdas, the compares of a rebuilt switch expression).

The `.x` project saves them (`CSharpDecompilerSettingsImpl`, own settings section), shows the page "C# (ILSpy 11)" under Decompiler and refreshes open tabs of this language when it changes. ✅ Language version (`LanguageVersion`, string: `1`…`7.3`, `8.0`…`14.0`, `latest`; `--csharp-version`, combo box on the page, saved): `CreateILSpySettings` creates ICSharpCode's settings for that version and the feature options are ANDed with them (before, they were assigned after the `Latest` ctor).    - ✅ Edit Method/Edit Class/Add Members (`DecompilationType.TypeMethods`, `DecompileTypeMethodsTransform.cs`): the whole top-level type is decompiled and the members are filtered with the old language's rules (properties/events whole, declaring types `partial`, hidden document without base types/attributes). Microsoft.WindowsDesktop.App), without which WindowsBase resolved to the Microsoft.NETCore.App facade.
